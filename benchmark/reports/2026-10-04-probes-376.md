# Probes for #376: requests nobody planned for

Date: 2026-10-04.
Commits: `97ccd9a` to `5d31199` on `feat/376-probe` (each run's `manifest.json` names its own).
Eight tasks in `benchmark/tasks/probes/`, one run each, in `claude-code` mode with `CODE_AMENDMENT_ENABLED=true`.
The point is to name failures, not to score the engine: eight single runs say what can go wrong, not how often.

## Method

Every probe asks for the same three-slide deck (why a build cache moved from a shared disk to an object store), takes the first design direction and the outline as planned, and then sends one follow-up message once the deck is finished.
The follow-up is the probe.
The eight runs share one base deck: the model's answers up to the follow-up were replayed from `probe-watermark/20261004-153455-claude-code`, so every follow-up starts from the same three pages and the results can be compared.
Requests the earlier runs had not seen were answered by hand.
Before writing an edit, the model read the deck with a script that printed every shape's name, position and colour, as the change step's directive asks.

For each probe the questions from #376 were:

- which tool the agent reached for;
- whether the result was valid;
- whether it collided with existing content;
- whether it survives a re-render.

Survival was tested by replaying each run's recorded change scripts through the loop's own replay (`edit_deck_with_code.replay`) over the deck as it was before the change, and comparing the result with the delivered deck.

## Failures found, and what fixed them

Each was fixed on this branch and recorded in `docs/DESIGN_DECISIONS.md` (sections 3, 4 and 13 and the evidence table).

1. **A `replace` spent rounds on pages it could not move** (`probe-watermark`, 2026-10-02).
   With two content arrangements and two flagged pages, the first `replace` swapped them and the second handed both back unchanged.
   Composition now records each page's alternatives, the render reports the slides that have none, and their findings go to a redraft (`6360af3`, `9da8518`).
2. **The amend backstop's script shipped unchecked** (`probe-watermark/20261004-151346`).
   It ran after validation had spent its budget, and the closing message listed the finding it had just fixed.
   A script edit now reopens validation for one more check (`1cd57be`).
3. **An amendment redrafted slides nobody asked to change** (`probe-watermark/20261004-152315`).
   The changed deck was judged afresh, so the empty space it was handed over with read as new, and a watermark request rewrote slide 2's copy.
   Findings the deck was handed over with are now reported, not reopened (`97ccd9a`).
4. **The benchmark failed every watermarked deck** (`probe-watermark`).
   Its geometry check counted the watermark as overlapping text, which the run's own validation already ignores (`cb66032`).
5. **A progress bar was refused as an ungrounded chart** (`probe-progress-bar/20261004-154000`).
   The grounding check matched the text `bar(`, which the script's own helper `bar` contained, and then `draw_bar`.
   The change step ran out of turns and the closing prompt still asked for the change.
   Figures are now read off the script's syntax (`75d91e4`), and a change that was not made is said to be not made (`9417cf8`).
6. **A declined change re-validated an untouched deck** (`probe-rotate-exhibit/20261004-154006`).
   A decline now restores what validation said at handover (`9417cf8`), and a script that only read the deck is no longer counted as a change to what shipped (`5d31199`).
7. **The ladder answered a script's defect by re-placing and redrafting a page** (`probe-hyperlink-terms/20261004-153956`).
   The first link script left the linked words in the theme's hyperlink blue on the dark cover.
   The ladder re-placed the cover, re-rendered (which also dropped an earlier repair to slide 3) and then redrafted the cover's copy.
   A finding the change's script caused now goes back to the change step, once; there a second script kept each link in its line's own colour, underlined (`38fa9f0`).
8. **Languages were refused for pages the engine derived** (the nine languages these runs authored).
   Five were refused because the stacked variant derived from one of their page kinds ran a frame off the canvas; the refusal named a frame the model never wrote.
   Unsound derived arrangements are now dropped and the authored kind kept (`d8bc6be`).
9. **The recolour probe's request was cut short** by YAML reading ` #E4572E` as a comment (`3f50e74`).

## What is still wrong

These are not fixed here; most are what layer 2 of #376 exists for.

- **An edit is a script, replayed.**
  It survives a re-render only because the loop runs it again, over whatever the new composition produced.
  The scripts here guard themselves ("content reaches the footer band", "the top-left corner is taken"), so after a re-render that moves content into that space the replay would skip the edit and log it, and the change would be gone from the deck.
  A typed overlay placed by composition would be checked against the page's frames on every render instead.
- **Every probe needed two model turns to read the deck before writing one edit**, and the first read script was refused by the sandbox gate for nesting loops four deep, which slide, shape, paragraph and run naturally are.
  An engine-aware read API (frames, safe zones, theme tokens) would make the read unnecessary.
- **A recolour reaches shapes, not the theme.**
  Anything drawn later from the theme's accent slots, or a page added by a later revision, would come back in the old colour.
- **A link takes the theme's hyperlink colour** unless the run carries Office's `hlinkClr` extension, which LibreOffice honours.
  In LibreOffice the linked words also change the line's leading: the first line of the slide 3 headline sits about 0.1in higher than before.
- **A watermark behind the content is hidden by any filled shape in front of it.**
  The validator does not flag it, since the copy stays legible.
- **No pictures and no network.**
  The coffee cup is a stand-in, and the QR code exists because the model wrote a QR encoder in the sandbox (about 4,500 characters).
  Both are what the asset path in #376 is for.
- **The base deck is not clean.**
  Every probe deck ends with two layout findings that were there before the follow-up: short material is laid out at full height, so slide 2's lower third is empty and slide 3's flow floats below its copy (#378).
  This is why every run fails `validation_converged`.

## Cost

Model calls per run: 35 to 42, of which 31 build the shared base deck.
Estimated input tokens per run: 214k to 252k (`claude-code` mode estimates at 3.5 characters per token; nothing was billed).
The follow-up itself took 4 to 11 calls, closing message included.
`watermark` wrote its edit straight away (5 calls); the other edits took two reads and one edit (7), `hyperlink-terms` a second edit and a second validation (11), and `rotate-exhibit` two reads and a reply (4).
Each validation is a vision call per page.
